# 校园无网服务器部署 Python 项目 · 通用指南

> 适用场景:学校 GPU/Linux 服务器**无法联网**(被校园网认证拦截,pip 装不了包),
> 但本地或 GitHub 能联网。任何 Python(+前端)项目都能照此部署。
>
> 核心思路:**联网的地方准备好一切 → 传到服务器 → 离线安装**。

---

## 一、先判断你的服务器卡在哪(诊断)

SSH 登录服务器,依次跑这几条,心里有数:

```bash
# 1) 系统与 Python
cat /etc/os-release | head -2
python3 --version
uname -m                      # x86_64 还是 aarch64,决定下哪种 wheel

# 2) 有没有 pip / venv
python3 -m pip --version      # 报 No module named pip = 没有
python3 -m venv --help        # 报 ensurepip not available = 缺 python3-venv

# 3) 能不能联网(关键)
curl -s -m 8 -o /dev/null -w "%{http_code}\n" https://pypi.org/simple/
#  返回 200 = 能联网(那直接在线装就行,跳过本指南)
#  返回 000 / SSL 证书错 / 卡住 = 不能联网(继续往下)
```

**典型症状**:`pip install` 报
`SSLError ... self-signed certificate` 或 `Could not find a version` ——
这就是校园网认证拦截,所有公网 pip 源都下不了包。

---

## 二、解决「没有 venv」(需联系管理员一次)

若 `python3 -m venv` 报 `ensurepip is not available`,说明缺系统包,
**需要 root 安装**(找老师/管理员,只需一次):

```bash
sudo apt install python3-venv python3-pip      # Ubuntu/Debian
# CentOS: sudo yum install python3-pip
```

装好后普通账号就能 `python3 -m venv` 建虚拟环境了(venv 自带 pip)。

> 注意:即使有了 venv+pip,**装包仍需联网**。无网的话继续走下面的离线方案。

---

## 三、核心:用 GitHub Actions 造离线依赖包

**为什么用 GitHub Actions**:服务器是 Linux,你的本地多半是 Windows/Mac,
平台不同,本地下的 wheel 在服务器跑不了。GitHub 提供免费 Linux 环境,
下出来的 wheel 与服务器平台一致,且你本地零安装。

### 3.1 在项目里加 workflow 文件

在仓库建 `.github/workflows/build-offline-wheels.yml`:

```yaml
name: Build Offline Wheels
on:
  workflow_dispatch:        # 手动触发
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"      # 改成与服务器一致的版本!
      - run: python -m pip install --upgrade pip wheel
      - name: Download wheels
        run: |
          mkdir -p offline_wheels
          pip download --dest offline_wheels --prefer-binary -r requirements.txt
          pip download --dest offline_wheels --prefer-binary pip setuptools wheel
          ls offline_wheels | wc -l
      - uses: actions/upload-artifact@v4
        with:
          name: offline-wheels
          path: offline_wheels/
```

**关键点**:
- `python-version` 必须和服务器的 `python3 --version` **大版本一致**(如都 3.12),否则 wheel 装不上。
- 不要加 `--platform`/`--only-binary=:all:` 等严格参数 —— runner 本身就是 Linux,
  原生 `pip download` 出来的就能用;加了反而报 `No matching distribution`。
- 如果项目用 PyTorch 且只需 CPU 版,加 `--extra-index-url https://download.pytorch.org/whl/cpu`
  避免拉几个 G 的 CUDA 版。

### 3.2 运行并下载

1. 推送 workflow 到 GitHub
2. 仓库页 → **Actions** → 左侧选该 workflow → **Run workflow**
3. 跑完(几分钟)进入该次运行,底部 **Artifacts** 下载 `offline-wheels`(zip)
4. 本地解压,得到一堆 `.whl` 文件的目录

## 四、准备其他大件(按需)

### 4.1 前端产物(若有前端且服务器无 Node)
本地 `npm run build`,把 `dist/` 一起传服务器,服务器只跑后端托管它,无需装 Node。

### 4.2 大模型 / HuggingFace 模型(若用)
模型从本地 `~/.cache/huggingface` 找到,**用 `cp -rL` 解符号链接导出成平整目录**
(直接打包会因 Windows/Linux 符号链接不兼容而断链),再传服务器,
代码里用本地路径加载(如设环境变量指向模型目录)。

### 4.3 数据库 / 数据文件
SQLite 等数据文件直接 scp 传,免去服务器重新初始化。

## 五、传输到服务器(本地执行)

```bash
# Windows 用反斜杠路径;Mac/Linux 用 /path。端口按实际改(示例 60042)
scp -P 60042 项目代码.tar.gz   用户@服务器IP:~/
scp -P 60042 offline_wheels.tar.gz 用户@服务器IP:~/
scp -P 60042 模型.tar.gz       用户@服务器IP:~/   # 若有
```

> 打包命令(本地):`tar -czf offline_wheels.tar.gz offline_wheels`

---

## 六、服务器离线安装

```bash
# 解压到工作目录
cd ~/你的工作目录
tar -xzf ~/项目代码.tar.gz
cd 项目目录
tar -xzf ~/offline_wheels.tar.gz -C .

# 建虚拟环境 + 离线装依赖(--no-index 完全不联网)
python3 -m venv .venv
./.venv/bin/python -m pip install --no-index --find-links=offline_wheels -r requirements.txt
```

`--no-index --find-links=目录` 是离线安装的关键:只从本地 wheel 目录找包,不碰网络。

---

## 七、启动 + 端口

```bash
# 注意避开已被占用的端口(如本机已有服务占 8000),换 8088 等
./.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8088
#   --host 0.0.0.0 才能从外部访问;127.0.0.1 只能本机
```

**外部访问不了时的两种办法**:

1. **SSH 隧道**(最简单,无需开端口,适合演示/调试):
   本地跑 `ssh -p 60042 -L 8088:localhost:8088 用户@服务器IP -N`,
   然后本地浏览器开 `http://localhost:8088`(隧道窗口别关)。

2. **开放端口**(正式对外):找管理员放行服务器防火墙/安全组的对应端口。

## 八、常见坑速查

| 现象 | 原因 / 解决 |
|------|------------|
| `ensurepip is not available` | 缺 python3-venv,找 root `apt install python3-venv` |
| `SSLError: self-signed certificate` | 校园网认证拦截,放弃在线装,走离线 wheel |
| `No matching distribution found` | 在线源拿不到包(被拦)/ 或 workflow 加了 `--platform` 严格参数 |
| 离线装报某包缺失 | offline_wheels 不全:确认 workflow 的 python 版本与服务器一致;有 `.tar.gz` 源码包说明该包无对应 wheel,需在 Actions 里补 |
| wheel 装不上(platform/version) | GitHub Actions 的 `python-version` 与服务器不一致,改成一致重跑 |
| `address already in use` | 端口被旧进程占:`pkill -f uvicorn` 后重启;或换端口 |
| 外部浏览器连不上 | 端口没对外开放,用 SSH 隧道,或找管理员放行端口 |
| 后台常驻(关 SSH 不掉) | `nohup ./.venv/bin/python -m uvicorn ... > run.log 2>&1 &` |

---

## 九、一句话总结流程

```
联网处(本地/GitHub)备好:wheel包 + 前端dist + 模型 + 数据
        ↓ scp
服务器:解压 → venv → pip install --no-index 离线装 → 启动
        ↓
访问:SSH 隧道 或 开放端口
```
