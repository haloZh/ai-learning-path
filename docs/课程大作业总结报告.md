## 一、项目概述

### 1.1 选题背景

在线学习平台普遍存在 **"千人一面"** 的资源分发问题：所有学生看到同一份目录、同一份习题顺序，平台知道学生答题对错却不改变后续学习路径。传统推荐系统只做行为相似度匹配，缺乏对知识结构的理解；单纯调用大模型又容易沦为"花哨的问答"，无法持续追踪学生状态。

本项目构建一个融合 **检索增强生成（RAG）** 与 **多智能体协作** 的个性化学习路径系统，实现 **"诊断 — 生成 — 调整"** 的完整闭环。

### 1.2 学科定位

首期锁定 **管综数学基础**（75 分，客观题），理由：
- 知识点先修关系清晰（算术→代数→几何→数据分析），**知识图谱易构建**；
- 题目全为客观题，**诊断结果完全可量化**（答对率→掌握度）；
- 管综考生备考焦虑真实，**"个性化路径"痛点刚性**。

### 1.3 交付形态

**Web 网页**，浏览器打开即用，免安装、跨设备。

## 二、系统设计

### 2.1 核心闭环

```
①画像录入 → ②诊断测验 → ③路径视图 → ④学习工作台 → ⑤评估看板
   建立画像    量化掌握度    生成个性化路径   按路径学习+反馈   回看学习全貌
```

### 2.2 多智能体协作（LangGraph 编排）

| Agent | 职责 | 输入 → 输出 |
|-------|------|------------|
| **诊断 Agent** | 量化各知识点掌握度 | 答卷 → mastery（0~1） |
| **规划 Agent** | 生成个性化学习路径 | 掌握度+知识图谱+资源 → path |
| **评价 Agent** | 对路径做五维客观打分 | path → 五维评分 |
| **优化 Agent** | 根据反馈动态调整路径 | 交互事件 → 新 path |

两条链路：诊断链（诊断→规划，首次跑）+ 优化链（每次反馈触发）；评价 Agent 异步执行，不阻塞主响应。

### 2.3 可解释性

每一次推荐都输出"为什么这样推荐"，例如：
- "先学一元二次方程 —— 掌握度最低，是管综核心考点，优先夯实基础"
- "跳过整式运算 —— 诊断中相关题目全部正确"

这是与 ChatGPT 类黑盒工具的本质区别，也符合教育类 AI"可控、可解释、不误导"的合规要求。

## 三、技术实现

### 3.1 技术栈

| 层级 | 选型 |
|------|------|
| 大模型 | 火山方舟 Doubao（开发期）/ 学院服务器 vLLM **Qwen3-8B**（部署） |
| Agent 编排 | LangGraph（4 Agent 协作） |
| RAG | bge-m3 向量编码 + Chroma 向量库 |
| 后端 | FastAPI + SQLAlchemy 2.0 |
| 前端 | Vue 3 + Element Plus + ECharts + KaTeX |
| 数据库 | SQLite |

### 3.2 数据规模（当前库）

| 表 | 数量 | 说明 |
|----|------|------|
| concepts | 33 | 知识图谱节点 + 先修关系 |
| questions | 389 | 题库（含 LaTeX 公式） |
| resources | 33 | 学习资源 |
| students | 17 | 学生画像 |
| mastery_snapshots | 22 | 诊断快照（保留历史） |
| learning_paths | 13 | 学习路径 |
| plan_evaluations | 18 | 路径评价留痕 |

### 3.3 评估体系

**双重评估，互补佐证路径质量：**

- **评价 Agent（LLM 主观）**：五维评分 —— 针对性 / 顺序合理性 / 可行性 / 个性化 / 资源匹配，总分 0-100；
- **客观指标（可计算）**：路径多样性、先修关系违反率、资源命中率、可行性比值、针对性得分。

### 3.4 工程健壮性

- **mock 兜底**：LLM 不可用时自动降级到本地启发式，接口不中断；
- **数据持久化**：8 张业务表落库，重启不丢路径；前端 sessionStorage 持久化，刷新不丢状态；
- **多 LLM 后端兼容**：配置三级回退（VLLM_* > LLM_* > ARK_*），切换大模型无需改代码。

## 五、服务器部署（学院 GPU 服务器）

### 5.1 部署成果

项目已部署到学院服务器（Ubuntu 24.04 / Python 3.12），接入本机 vLLM **Qwen3-8B** 大模型，通过 8088 端口运行，可经 SSH 隧道访问完整系统。

### 5.2 关键技术挑战与解决

部署环境为 **完全无外网的隔离服务器**（校园网认证拦截），带来三重困难，逐一解决：

| 挑战 | 解决方案 |
|------|---------|
| 服务器无法联网装依赖 | 用 **GitHub Actions** 在同平台（Linux x86_64 / py3.12）下载离线 wheel 包 |
| 平台不匹配（本地 Windows） | 借 GitHub 云端 Linux 环境产出平台一致的依赖 |
| 缺 pip/venv、bge-m3 模型无法在线下载 | 离线安装（`pip --no-index`）+ 本地导出模型 scp 传输 |

形成可复用的**"联网处准备 → 搬运 → 无网处离线组装"**通用部署方法论，已沉淀为团队文档。

### 5.3 LLM 切换适配

从火山方舟 Doubao 切换到 Qwen3-8B（vLLM）仅需改配置：
- 兼容 OpenAI 接口，代码逻辑不变；
- 增加 JSON 输出容错（处理 Qwen3 思考标签、markdown 包裹等）。

## 七、项目总结

### 7.1 完成的核心价值

1. **闭环而非一次性推荐**：诊断—生成—调整完整跑通，学习反馈实时优化路径；
2. **可解释而非黑盒**：每步推荐附理由，全程推理日志可追溯；
3. **量化而非感觉**：掌握度、路径质量均有客观指标；
4. **可落地**：从开发到学院服务器真实部署，接入国产大模型 Qwen3-8B。

### 7.2 人才培养目标达成

- **产品思维**：从痛点调研到 Persona 到功能设计的完整链路；
- **技术落地能力**：多智能体 + RAG + 全栈开发 + 复杂环境部署；
- **问题分析能力**：无网部署等真实工程难题的系统性拆解与解决。

### 7.3 后续可扩展方向

- 扩充题库与真实资源链接，提升 RAG 资源匹配质量；
- 引入真实考生交互数据，验证个性化路径的学习效果提升；
- 横向扩展到管综逻辑、写作等子科目。
